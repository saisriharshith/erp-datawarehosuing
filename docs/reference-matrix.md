# Reference Comparison Matrix

This matrix provides a side-by-side architectural and functional comparison between **InsightFace**, the legacy **Attendance Reference System**, and the **New AI-Powered Face Recognition College Attendance Management System**.

| Capability | InsightFace (`deepinsight/insightface`) | Attendance Reference (`Face-Recognition-Attendance-System`) | New System (`Modern College Attendance SaaS`) |
| :--- | :--- | :--- | :--- |
| **Face Detection** | Deep learning SCRFD (Sample and Computation Redistribution for Face Detection) & RetinaFace in ONNX. Highly robust across poses and lighting. | Browser-side SSD MobileNet v1 via `face-api.js`. Medium accuracy, resource-heavy in browser. | Server-side InsightFace SCRFD with multi-scale pyramid detection and landmark localization via ONNX Runtime. |
| **Face Recognition** | ArcFace / SubCenter-ArcFace / PartialFC margin loss representations. Generates normalized 512-D embeddings. | `face-api.js` FaceRecognitionNet (ResNet-34 based, 128-D descriptors). | ArcFace 512-dimensional L2-normalized embeddings via InsightFace `ArcFaceONNX`. |
| **Embeddings Management** | NumPy vectors; raw feature arrays. No storage or indexing included. | Browser memory descriptors computed on the fly on each session start from fetched images. | Stored in MongoDB collection `face_embeddings` with associated metadata; cached in-memory NumPy/scikit-learn cosine similarity index for sub-millisecond recognition. |
| **Face Enrollment** | No enrollment application workflow; raw Python demo scripts. | Admin creates student and takes 5 webcam images sent as base64 and saved on server disk. | Guided interactive camera workflow: validates single face, face box size, pose, sharpness/blur, lighting; captures 5–10 samples; generates embeddings server-side; stores originals in ImageKit. |
| **Multiple Samples** | Supported algorithmically (pairwise cosine comparison). | Saves 5 images as `1.png`..`5.png` in folder; computes 5 descriptors per student in JS. | Stores 5–10 embedding vectors per student in MongoDB `face_embeddings`; recognition aggregates similarity across candidate samples with outlier rejection. |
| **Liveness / Anti-Spoofing** | InsightFace 2.0 RGB liveness addon (`liveness.onnx` score) + crop bounding box checks. | None. Vulnerable to printed photos and phone screen replays. | Hybrid defense: InsightFace RGB liveness model + interactive motion/challenge protocol (blink/head turn) during enrollment and verification. |
| **Student Management** | None. | Flat MySQL table `tblstudents` (first/last name, reg number, email, course, faculty, image JSON). | Rich MongoDB `students` collection: student ID, full name, email, phone, course_id, year, section, status, face_enrollment_status, biometric metadata, timestamps. |
| **Lecturer Management** | None. | Flat MySQL table `tbllecture` (name, email, plain/MD5 password, faculty). | MongoDB `lecturers` collection linked to user auth; department/faculty assignment; course/unit teaching assignments; session history. |
| **Courses** | None. | `tblcourse` (Id, name, facultyID, dateCreated, courseCode). | MongoDB `courses` collection: course_code, title, department, credits, semester/year, active flag, enrolled students count. |
| **Units / Subjects** | None. | `tblunit` (Id, name, unitCode, courseID, dateCreated). | MongoDB `units` collection: unit_code, name, course_id, credit_hours, syllabus/description, assigned lecturers. |
| **Venues** | None. | `tblvenue` (Id, className, facultyCode, currentStatus, capacity, classification). | MongoDB `venues` collection: venue_code, name, building, room_number, capacity, venue_type (lecture_hall, lab, seminar_room), camera_preset. |
| **Attendance Sessions** | None. | No session model. Records only store `dateMarked` without start/end or lecturer context. | Explicit MongoDB `attendance_sessions` collection: course_id, unit_id, venue_id, lecturer_id, status (`CREATED`, `ACTIVE`, `COMPLETED`, `CANCELLED`), started_at, ended_at, total_present. |
| **Duplicate Prevention** | None. | None. Duplicates are possible if multiple requests are posted. | Database-level unique compound index on `attendance_records` `(session_id, student_id)`. Prevents duplicate attendance at the database engine level. |
| **Reports & Export** | None. | Basic server-generated Excel table download (`download-record.php`). | Comprehensive reporting engine: Daily, Weekly, Monthly, Student-wise, and Course-wise attendance reports; exportable as CSV, Excel (.xlsx), and formatted PDF. |
| **Authentication** | None. | Basic PHP session with legacy password hashing (`password_verify`). | Modern RESTful JWT (JSON Web Token) authentication; Argon2/bcrypt password hashing; refresh tokens; secure token invalidation. |
| **Authorization** | None. | Basic URL-based PHP `$_SESSION` role check. | Declarative FastAPI dependency injection (`get_current_user`, `require_role(["ADMIN", "LECTURER"])`); backend-enforced RBAC. |
| **Database** | None. | MariaDB/MySQL with MyISAM/InnoDB tables and raw SQL queries. | Modern MongoDB (Atlas / local container) with `motor` async driver, indexed collections, transactions, and Pydantic v2 data validation models. |
| **Image Storage** | Local filesystem. | Stored directly in the web root filesystem `resources/labels/{regNo}/`. | **ImageKit Cloud Storage CDN**: Secure cloud upload via ImageKit SDK, CDN optimization, transformation URLs, and encrypted private credentials. |
| **User Interface** | CLI tools and PyQt desktop GUI in 2.0. | AdminLTE-inspired PHP/HTML/CSS templates with basic JS modals. | Premium SaaS UI: React 18 + Vite + TypeScript, Tailwind CSS, shadcn/ui components, Lucide icons, responsive layout, dark/light mode, and Recharts analytics. |
